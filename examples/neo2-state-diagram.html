Key Neo 2.0 Mechanisms
Phase 1: Intent Declaration

Agents declare intent before work begins. Neo records INTENT_DECLARED events and enforces authorization gates. Conflicts at this stage prevent wasted generation.

Phase 2: Temporal Handoff (Neo 2.0)

When work completes, HANDOFF_PENDING state enables transfer of context independent of PRs. Next dev can CONSUME prior work's findings, dependencies, and risks without merging yet.

Phase 3: Context Invalidation

When paused agent's context becomes stale (another dev changed a dependency), CONTEXT_INVALIDATED fires. Paused dev is woken to REVALIDATE or re-analyze before resuming.

Phase 4: Reviewer Provenance

Every COMMIT_CREATED and REVIEW_* event captures who did what and when. Enables traceability, audit trails, and blame analysis for complex edits across multiple agents.

Phase 5: Agent Autonomy

Events feed an autonomy engine that learns which conflicts are real vs. false positives. Over time, Neo improves risk scoring and adapts decision gates.

Development Memory

All events append to Development Memory queryable by resource, actor, time range, or type. Enables pattern discovery: "Who typically works on this function?" "What changed in the last hour?"

Event Flow Example: Two-Developer Scenario
1. DEVELOPER_REGISTERED (dev1)
2. INTENT_DECLARED (dev1 on auth.py::login)
3. WORK_STARTED (dev1)
4. STATE_TRANSITION (AVAILABLE → EDITING)
5. RESOURCE_CLAIMED (dev1 on auth.py::login)
6. DEVELOPER_REGISTERED (dev2)
7. INTENT_DECLARED (dev2 on auth.py::login) ← SAME RESOURCE!
8. RESOURCE_CONFLICT_DETECTED (dev1 ↔ dev2, risk: 85)
9. INTENT_BLOCKED (dev2)
10. STATE_TRANSITION (AVAILABLE → CONFLICT_WAITING)
11. WORK_PAUSED (dev2, checkpoint saved)
12. WORK_COMPLETED (dev1)
13. STATE_TRANSITION (EDITING → BOTH_DONE)
14. HANDOFF_CREATED (dev1 → dev2)
15. STATE_TRANSITION (BOTH_DONE → HANDOFF_PENDING)
16. RESOURCE_RELEASED (auth.py::login)
17. HANDOFF_ACKNOWLEDGED (dev2)
18. CONTEXT_SNAPSHOT_CREATED (dev2, prior work snapshot)
19. WORK_RESUMED (dev2, from checkpoint)
20. STATE_TRANSITION (CONFLICT_WAITING → PENDING_REVIEW)
21. WORK_COMPLETED (dev2)
22. STATE_TRANSITION (BOTH_DONE → IN_PR)
23. BRANCH_CREATED (feature/auth-oauth2)
24. COMMIT_CREATED (dev2, with dev1 as co-author via provenance)
25. PR_CREATED (#123)
26. REVIEW_REQUESTED (#123)
27. REVIEW_COMPLETED (approved)
28. STATE_TRANSITION (IN_PR → APPROVED)
29. PR_MERGED (merge commit abc123)
30. STATE_TRANSITION (APPROVED → MERGED)
